## 📖 Описание проекта  
Наш проект для учебной практики — это прототип симулятора рутинных процессов с элементами психологического хоррора.  
  
Идейным ядром проекта выступает концепция профессионального выгорания, когнитивной перегрузки и обесценивания собственного труда. В отличие от классических хорроров, игра генерирует чувство тревоги и дискомфорта не через скримеры, а посредством жесткой математической модели: тайм-прессинга, многозадачности и строгой системы прогрессивных штрафов.

## ⚙️ Технологии и ключевые фишки проекта  
Проект разработан на базе движка **Unreal Engine 5** с использованием системы визуального скриптинга **Blueprints**.  
  
**Ключевые геймплейные системы:**  
* **Архитектура тайм-прессинга:** Реализована система независимых таймеров. «Таймер З» контролирует жесткие дедлайны обработки текущей партии. «Таймер П» штрафует игрока за простой производственной линии.  
* **Система модульной сложности:** Интегрированы 3 фазы (пресета) сложности, динамически сужающие временные рамки, увеличивающие шанс генерации бракованных объектов и повышающие множители штрафов для симуляции нарастающего истощения.  
* **Инвентарь и сериализация:** Разработана механика упаковки/распаковки объектов (`BP_Box`) с сохранением всех атрибутов предмета (цвет, статус проверки, форма) в специальную структуру данных (`ItemData`).  
* **Оптимизированный менеджмент объектов:** Использование триггерных зон (`Box Collision`) и массивов для массовой утилизации объектов со сцены без падения производительности.  
  
## 🧩 Уникальные вызовы и решенные проблемы  
Одной из главных архитектурных проблем в процессе разработки стала **потеря состояний объектов при передаче данных между системами**.  
  
**Суть проблемы:** Объекты (`BP_Main`) генерировались с флагом неизвестности (`ToCheck = True`) и скрывались под черным материалом до проверки в сканере (`BP_Scanner`). Однако при помещении не отсканированного предмета в коробку и последующем его извлечении, объект появлялся с уже раскрытым истинным цветом. Система инвентаря непреднамеренно брала на себя функционал сканера, ломая баланс игры и позволяя избегать штрафов.  
  
**Решение:** Проблема была локализована на этапе сериализации. Структура `ItemData` внутри класса коробки была расширена добавлением булевой переменной `toCheck`. Был переписан алгоритм инициализации при распаковке: теперь система принудительно проверяет этот флаг и, если объект не проходил легальное сканирование, корректно возвращает ему исходный статус неизвестности (черный материал). Это полностью закрыло эксплойт и стабилизировало геймплейный цикл.
